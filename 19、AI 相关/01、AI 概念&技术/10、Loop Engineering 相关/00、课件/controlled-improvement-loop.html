CONTROLLED IMPROVEMENT

Trace 不是改进，经过验证并安全发布才是

真正的外层 Loop 必须把相关性观察转化为可归因、可回归、可回滚的系统变更

01

生产运行

任务、结果、成本与环境状态

02

证据沉淀

Trace、失败样本、用户反馈与事故

03

问题归因

区分模型、上下文、工具、数据与规则问题

04

候选修改

Prompt、Tool、Policy、Eval 或模型版本

05

离线评估

基准、回归、成本、延迟与安全检查

06

审批灰度

责任人确认、有限流量与可观测发布

07

Harness vN+1

比较真实结果，保留版本、发布与回滚能力

伪闭环看到 Trace → Agent 改 Prompt → 直接上线
可信闭环证据 → 归因 → 候选 → Eval → 人审 → 灰度 → 发布／回滚
经过验证的新 Harness 只进入未来 Task Run，不在线改写当前任务
外层 Loop 的核心不是“自动修改”，而是“让每次修改都留下可验证的责任与证据”
