TASK LIFECYCLE → RESPONSIBILITY BOUNDARY

一个真实任务，需要四种相互制衡的 Loop

从任务发生到系统变好：何时启动、如何推进、谁判完成、如何变好

01 · START
要解决什么事件应该成为一个任务
由它负责

Event-driven Loop

监听业务事件，筛选并创建可追踪的 Task Run

何时启动把启动权从人工接力中分离出来
02 · ACT
要解决开放任务如何持续向前推进
由它负责

Agent Loop

根据环境反馈连续判断与行动，直到产生候选结果

如何推进获得行动权，但不能为自己验收
03 · VERIFY
要解决候选结果是否真的达到要求
由它负责

Verification Loop

用测试、环境 Outcome、Grader 或人审决定通过、返工与升级

谁判完成完成证明不再由执行者签发
04 · IMPROVE
要解决重复暴露的问题如何不再重演
由它负责

Improvement Loop

把跨任务证据转成 Harness 修改候选，经 Eval 与治理后进入下一版本

如何变好改进未来系统，不在线改当前任务
一条记忆主线：启动 → 推进 → 完成 → 变好
