## **OLAP** 钻取思维与知识库路由映射

### 一、核心结论

**OLAP** 的 `drill-down / roll-up` 可以迁移成当前知识库路由里的纵向控制模型：

```text
搜索词 / 关键词
  -> 规范化 / 别名归一
  -> facet 并行打标
  -> scenario 场景轴下钻
  -> parent 回退继承
  -> 人群硬闸
  -> SKU 裁决
  -> 下游内容生产
```

这篇资料只解决一个问题：

> 为什么当前知识库应采用 **scenario** 单轴漏斗、平铺 `facet`、`parent` 回退和 **SKU** 裁决，而不是把所有维度都做成嵌套树

### 二、最小概念

| **OLAP** 概念 | 含义 | 知识库路由映射 |
| --- | --- | --- |
| `drill-down` | 从粗粒度进入细粒度 | 从通用场景进入更具体子场景 |
| `roll-up` | 从细粒度回到粗粒度 | 子场景缺字段时回到 `parent` 继承 |
| 层级轴 | 存在粒度上下级的维度 | **scenario** 场景轴 |
| 维度条件 | 横向描述条件 | 人群、部位、分型、症状等 `facet` |

关键不是引入 **OLAP** 技术栈，而是借用它的粒度控制纪律：

- 该下钻的轴下钻
- 该平铺的维度平铺
- 该回退的节点能回退
- 该业务裁决的位置统一收口

### 三、当前路由映射

| 当前知识库路由动作 | **OLAP** 类比 | 工程含义 |
| --- | --- | --- |
| 通用场景进入子场景 | `drill-down` | 从 `surgery_postop` 下钻到甲状腺术后、双眼皮术后、耳洞术后等 |
| 子场景回到通用场景 | `roll-up` | 向 `parent` 继承公共痛点、公共规则或候选 **SKU** |
| 人群、分型、部位、症状打标 | 维度条件 | 作为平铺 `facet` 参与过滤，不进入层级树 |
| `facet` 求交集 | 查询过滤 | 类似 `WHERE 人群 = 儿童 AND 分型 = 增生` |
| **SKU** 裁决 | 漏斗收口 | 根据场景、部位、阶段、人群硬闸完成候选裁决 |
| 下游内容生产 | 路由结果消费者 | 内容类型、风格、标签、合规消费结果，不回写主轴 |

可压缩为：

```text
纵向：scenario 下钻 / parent 回退
横向：facet 打标 / 相交过滤
收口：人群硬闸 / SKU 裁决
下游：内容生产消费路由结果
```

### 四、为什么只有 **scenario** 进漏斗

一个维度适合成为层级轴，需要同时满足两个条件：

- 真有 `is-a` 嵌套关系
- 确实需要向 `parent` 回退继承

**scenario** 满足这两个条件：

```text
术后场景
  -> 外科术后
  -> 甲状腺术后
```

“甲状腺术后”是“术后场景”的子类型，也需要继承通用术后场景的公共痛点、合规边界和候选规则

人群、分型、部位、症状默认不进入漏斗，它们更适合平铺打标：

```text
人群 = 儿童
分型 = 增生
部位 = 颈部
症状 = 发红 / 凸起 / 摩擦
```

### 五、为什么不能多轴嵌套

把场景、人群、分型、部位都做成树，会导致组合爆炸：

```text
术后
  -> 儿童
    -> 增生
  -> 成人
    -> 增生
```

问题：

- 叶子节点数量按维度相乘
- 新增一个标签会引发整棵树膨胀
- 同一规则会在多个分支重复维护
- “儿童 + 增生”这类组合被迫在每个场景下复制

替代方案：

```text
场景轴负责纵向下钻
facet 负责横向打标
查询时做相交收敛
SKU 层做最终裁决
```

示例：

```text
搜索词：儿童甲状腺术后增生
  -> 场景 = 甲状腺术后
  -> 人群 = 儿童
  -> 分型 = 增生
  -> 交集过滤
  -> SKU：儿童适用产品进入候选
```

### 六、`parent` 回退不是失败

`roll-up` 在当前知识库中对应 `parent` 回退，它是继承和纠偏机制，不是路由失败

典型用途：

- 子场景没有独立痛点，继承通用场景痛点
- 子场景没有独立候选 **SKU**，继承父节点候选集合
- 搜索词命中过细或过偏，需要回到上级重新组合 `facet`
- 当前节点只负责场景定位，后续继续由平铺 `facet` 和 **SKU** 裁决收口

示例：

```text
甲状腺术后
  -> 缺少公共合规说明
  -> 回退到 surgery_postop
  -> 继承术后通用合规边界
  -> 结合部位 / 分型 / 人群做 SKU 裁决
```

### 七、工程价值

- 漏斗保留细粒度条件，避免搜索词直接跳到 **SKU**
- 单轴层级避免多维建树，只有满足 `is-a` 和 `parent` 回退的轴才进漏斗
- `parent` 回退减少重复配置，让子场景继承通用规则
- 下游内容只消费路由结果，不回写 **scenario** 主轴

### 八、边界与误区

- **OLAP** 只是分析类比，不是当前项目的技术栈
- `drill-down` 不等于所有维度都要下钻，能平铺打标就不进层级
- `roll-up` 不等于失败，`parent` 回退是继承和纠偏机制
- 知识库路由不是目录树，而是 **scenario**、`facet`、**SKU** 和下游消费的协作

### 九、可复用结论

当前知识库路由借用 **OLAP** 的 `drill-down / roll-up` 思维，让 **scenario** 负责下钻和回退，让 `facet` 负责横向过滤，最后由 **SKU** 裁决收口
