## **OLAP** 钻取思维：层级化信息空间中的受控下钻与回退

### 一、核心模型

**OLAP** 的 `drill-down / roll-up` 可以抽象成一个通用认知模型：

> 在层级化的信息空间里，做受控的下钻与回退

“受控”是关键：

- 该下钻的地方下钻
- 该平铺的维度平铺
- 该回到父层的时候能回退
- 不把所有维度都拆成越来越深的树

### 二、最小概念

**OLAP** 是 **Online Analytical Processing**，通常用于按多维度观察数据，其中部分维度内部存在粒度层级

典型层级：

- 时间：年 -> 季 -> 月 -> 日
- 地区：全国 -> 省 -> 市 -> 门店
- 商品：品类 -> 子类 -> 单品

本文只需要两个操作：

| 操作 | 含义 | 方向 | 迁移价值 |
| --- | --- | --- | --- |
| `drill-down` | 从粗粒度进入细粒度 | 向下 | 理解层级轴如何收窄 |
| `roll-up` | 从细粒度回到粗粒度 | 向上 | 理解回退与继承 |

真正值得迁移的不是 **OLAP** 技术栈，而是“在层级空间里可上可下地移动粒度”的纪律

### 三、什么该进层级

一个维度适合提升为层级轴，需要同时满足两个条件：

- 真有 `is-a` 嵌套关系，子类确实是父类的一种
- 确实需要向父层回退继承，子节点没配全时能继承父节点字段

示例：

```text
商品
  -> 家电
  -> 冰箱
```

“冰箱”是“家电”的子类型，也可能需要继承“家电”的通用规则，这类维度适合做层级轴

而颜色、尺寸、材质、适用人群这类维度，通常更适合作为平铺分面：

```text
颜色 = 白
容量 = 大
能效 = 一级
人群 = 家用
```

判断纪律：

> 能不提升为层级轴就不提升，能平铺打标就平铺打标

### 四、为什么不能多轴嵌套

多轴嵌套会导致组合爆炸

例如把品类、人群、颜色都嵌进树：

```text
家电
  -> 家用
    -> 白色
  -> 商用
    -> 白色
```

再增加“容量”轴，每个分支都要复制一遍

后果：

- 叶子节点数量按维度相乘
- 新增标签会引发整棵树膨胀
- 同类规则要在多个分支重复维护
- “家用 + 白色”这类组合被迫在多个位置复制

替代方案：

```text
层级轴负责纵向下钻
分面负责横向打标
查询时做相交收敛
```

示例：

```text
查询：家用白色大容量冰箱
  -> 层级轴 = 家电/冰箱
  -> 颜色 = 白
  -> 人群 = 家用
  -> 容量 = 大
  -> 交集过滤
  -> 命中候选
```

### 五、回退不是失败

`roll-up` 对应回退到父层，它是继承和纠偏机制，不是路由失败

典型场景：

- 子节点没有独立属性，向父节点继承公共属性
- 子节点没有独立候选，向父节点继承候选集合
- 请求命中过细或过偏，需要回到上级重新组合分面
- 当前节点只负责定位粗粒度，后续继续靠平铺分面过滤

示例：

```text
冰箱
  -> 缺少某条公共规则
  -> 回退到家电
  -> 继承家电通用规则
  -> 再结合颜色 / 容量 / 人群做进一步过滤
```

回退能力的价值是减少重复配置，并让子节点默认继承父层通用规则

### 六、与分面打标的关系

`drill-down / roll-up` 只解释纵向层级轴，不能替代横向分面打标

两者分工：

- 平铺打标是数据侧静态结构，定义颜色、容量、人群等字段并给对象贴值
- 相交收敛是查询侧动态操作，运行时把多个条件做 `AND` 过滤

数据库类比：

```text
平铺打标 = 建字段 + 填值
相交收敛 = WHERE 条件 + AND 过滤
```

一个稳定的信息空间通常是：

```text
纵向：层级轴下钻 / 回退
横向：分面打标 / 相交
```

纵向管粒度深浅，横向管条件叠加，两者协作才能既精确又不膨胀

### 七、边界与结论

重点保留四条边界：

- **OLAP** 只是分析方法，不代表要引入数据仓库、**BI** 系统或多维分析引擎
- `drill-down` 不等于所有维度都要越拆越细，只有满足两个必要条件的轴才提升为层级
- `roll-up` 不等于失败，回退是继承和纠偏机制
- 层级化信息空间不是目录树，而是“少数层级主轴 + 平铺分面 + 谓词过滤”的协作

可复用结论：

> **OLAP** 的 `drill-down / roll-up` 提供的是“层级化信息空间中的受控下钻与回退”思维，让真正需要层级的轴负责纵向收窄和父层继承，让其余维度作为平铺分面负责横向过滤
