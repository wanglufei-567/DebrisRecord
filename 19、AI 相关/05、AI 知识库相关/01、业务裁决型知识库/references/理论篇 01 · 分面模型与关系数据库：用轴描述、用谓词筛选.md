## 分面模型与关系数据库：用轴描述、用谓词筛选

### 一、核心模型

**Facet**、关系型数据库和维度建模可以放进同一个认知模型：

> 用独立的轴描述对象，再用谓词筛选对象

它们共享的底层地基是集合论和谓词逻辑：

- 集合论管“有哪些、怎么算”
- 谓词逻辑管“用什么判断条件圈出要的对象”

最小因果链：

```text
先定义对象可能落在哪些描述轴上
再用判断条件从对象集合中筛选目标子集
```

### 二、概念链

| 概念 | 最小解释 | 例子 |
| --- | --- | --- |
| 值 | 一个具体取值 | 红、大号、长袖 |
| 轴 / 维度 | 一类可取值的位置 | 颜色、尺码、袖长 |
| 组合 | 多个轴的值放在一起 | 红色 + 大号 + 长袖 |
| 空间 | 所有可能组合构成的全集 | 所有颜色、尺码、袖长的组合 |
| 点 | 空间中的一个具体组合 | 一件具体 T 恤 |
| 子集 | 从全集里筛出的一部分 | 所有红色 T 恤 |
| 谓词 | 判断是否留下的条件 | 颜色等于红 |

压缩成一句话：

> 轴定义空间，点落在空间里，谓词从空间里切出子集

### 三、映射到关系型数据库

关系型数据库可以理解为：

> 在笛卡尔积空间里，用谓词切子集

| 因果链概念 | 关系数据库构件 | T 恤例子 |
| --- | --- | --- |
| 值 | 单元格的值 | `'红'` |
| 轴 / 维度 | 列 `column` | `color` |
| 组合 | `CROSS JOIN` / 笛卡尔积 | 颜色 x 尺码 x 袖长 |
| 空间 | 各列取值的笛卡尔积全体 | 所有可能的 T 恤组合 |
| 点 | 行 `row` / 元组 `tuple` | `(1, '红', '大号', '长袖')` |
| 子集 | 查询结果集 | 满足条件的若干行 |
| 谓词 | **WHERE** 条件 | `color = '红'` |
| 复合谓词 | `AND / OR / NOT` | `color = '红' AND size = '大号'` |

示例：

```sql
SELECT *
FROM tshirts
WHERE color = '红'
  AND size = '大号';
```

这不是在“修饰”一件 T 恤，而是在用两个判断条件切出一个子集

`color = '红'` 和 `size = '大号'` 都是谓词，两个谓词用 `AND` 连接后形成复合谓词

### 四、三组关键区分

#### 1. 轴 / 值

轴是一类可取值的位置，值是轴上的具体取值：

```text
轴：颜色
值：红

轴：尺码
值：大号
```

判断标准：

- 能取多个值、值之间可替换的是轴
- 落在轴上的确定取值才是值
- 把值误当成轴，会把结构拆得过碎
- 把轴误当成值，会丢失组合能力

#### 2. 正交 / 耦合

正交轴可以相对独立地取值和组合：

```text
颜色 = 红
尺码 = 大号
袖长 = 长袖
```

这些描述不必嵌成一棵树，需要时做相交过滤即可

耦合约束是另一层规则：

- 某种面料只适用于特定品类
- 某些取值组合在业务上被禁止
- 合规或安全边界要求某些组合不能出现

正交解决组合能力，耦合解决有效性，二者不能混为一层

#### 3. 组合 / 穷举

穷举是提前把每一种组合写成独立叶子节点：

```text
品类
  -> 儿童款
    -> 红色
      -> 大号
  -> 成人款
    -> 红色
      -> 大号
```

组合是把每个轴平铺打标：

```text
品类 = 上衣
人群 = 儿童
颜色 = 红
尺码 = 大号
```

组合优于穷举，因为新增维度不需要复制整棵树，运行时通过条件相交收窄候选集合

### 五、与 **Facet** 和维度建模的关系

**Facet**、关系型数据库和维度建模不是谁抄谁，而是共享“集合论 + 谓词逻辑”的不同工程应用：

- **Facet** 分类：用若干独立分面描述对象，检索时按分面组合
- 关系型数据库：用列描述元组，用 **WHERE** 谓词组合筛选
- 维度建模：用维度描述事实，按维度切片、切块、聚合

共同点：

```text
先用正交轴把对象展开成可判断字段
再用谓词从可能空间里切出子集
```

差异只在工程侧重和术语，不在底层逻辑

### 六、边界与结论

重点保留五条：

- 谓词不是修饰词，而是可判断真假的筛选条件
- 不是所有标签都适合做层级树，只有真正存在 `is-a` 嵌套且需要父层回退继承的轴才值得层级化
- 正交轴不等于没有约束，禁止组合、业务校验、合规边界需要单独处理
- 组合能力不能替代规则，组合解决结构爆炸，约束解决有效性
- **SQL** 只是解释模型，同一套“轴 + 谓词”思维也可以落在文档数据库、标签系统和搜索过滤器上

可复用结论：

> 好的结构设计不是把所有组合穷举成树，而是让真正需要层级的轴承担纵向嵌套，让其余维度保持平铺分面，再用谓词过滤和约束校验完成收敛
